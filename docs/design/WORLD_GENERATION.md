# 无限地表世界生成 D05
v2.0 · 2026-11-27 · 算法契约与初始参数，待 G3 验证
依赖 D02、D03。非目标：地下层、地形自由雕刻、真实水文学/流体模拟。

## 坐标与确定性
Tile = 有符号整数 (x,y)，世界以地块计；Chunk 32×32；Region 16×16 Chunk = 512×512 Tile。chunkX=floor(x/32)，localX=x-32*chunkX（0..31），Y同理；region 用 floor 除法。禁止负数使用截断取整。设计安全上限 |tile|≤1,000,000，超过提示地图边界（技术保护、普通探索不可见，待测试）；绝不宣称数学无限。全局整数坐标用于逻辑；画面以当前 Chunk/原点重定位，避免 WebGL 浮点精度损失。ID 由 generatorVersion、seed、类型、全局坐标/模板实例和局部槽号导出。

管理员创建唯一世界时选择Seed，UTF-8 NFC固定编码，空值使用随机128位十六进制；固定哈希和 PRNG 实现及测试向量，严禁 Math.random/时间/加载顺序参与地图。算法函数纯输入输出；按层使用不同 salt，禁止共享会受加载顺序影响的 RNG。噪声实现及依赖锁版本，阈值附近采用量化结果，跨浏览器黄金测试通过才发布 generatorVersion。生成器升级不得让已有存档重建不同底图；见 D11。

## 生成管线
1. 全局连续宏观高度/湿度/温度场，Simplex 多尺度噪声（候选波长1024、256、64、16 tile、振幅1/.5/.25/.125；量化到整数）。五类区域：草地、森林、湿地/河流、丘陵/山地、海岸/沙滩；水域为地表类型而非第六生态群系。水域阈值和坡度待样片；草地优先出生。通过低频场生成多片大陆与岛屿，不模拟全球气候。
2. 区域级水系：每条共享边由 canonical edge key（两个 region 坐标排序）生成同一组河流通道与位置、宽度和切向；邻区必须共享接口。选择宏观高度较低的邻区为候选流向（同高以坐标总序破平，禁止逆序环）。区域内对通道使用粗网格最小代价路径+平滑样条，确定性排序；可在低地生成湖泊/海湾。源头可在区域内起始，终点必须接水面/湖或有效出口；不得无故断在区块/区域边界。不承诺真实全局水文学，避免递归追踪无界上游；G3 验证接缝、河流连贯与可达性，不达标修订 ADR。
3. 聚落与道路：每 Region 根据独立 salt 产生0–2候选锚点；检查干燥平坦地形、与水源的距离、模板足迹、周围 Region 候选。跨区冲突以全局稳定优先级选胜者；共享道路端口由同一 edge key 确定，粗网格寻路避开深水/陡坡，必要时桥梁。不强制所有远区道路都联网。预制村庄模板5种，出生点附近保证至少一个可达交易点。
4. 生物群系按温湿高、水距离确定；用多尺度区域分布减少噪声椒盐。资源/树木/动物出生点使用 coordinate hash 与邻域间距规则，建筑、路径和水体不被树木覆盖。跨边界大 sprite 由接地点所属 Chunk 唯一拥有，渲染查询含足够 halo。
5. 地块分类后按8邻域 bitmask autotile（角只有相邻边成立才连接），图集映射固定。对每 Chunk 使用至少1 tile 邻域生成；大对象/道路/水系通过更大的查询 halo；两侧从同一全局场采样。季节只改变视觉/资源状态，不改变基础地形和永久 ID。

## 出生与可达性
Seed 确定候选顺序，从原点附近搜索（初值半径256 tile）；要求5×5 连续可走公共出生草地，附近另有可申领的可建草地、100 tile 内淡水/木材/石材、256 tile 内可达交易点；以可走图 BFS 验证。若无候选，用固定版本的出生安全覆盖层在原点附近生成草地、资源、浅水边和桥/道路、交易点，覆盖层也确定性，不取随机 Seed 重试。禁止生成玩家无法离开的孤岛。普通玩家不得修改海拔、水体或自然村落。桥梁跨有限宽水格、两端接可走陆地；详见 D06。

## 生命周期
初始活跃3×3、加载5×5，以玩家 Chunk 为中心，额外按视口、移动方向预取；渲染范围与模拟范围分离，硬预算见 D12。服务器按兴趣范围并集请求权威生成 → 校验 epoch/generation → 加载共享增量 → 应用离屏结算 → 激活碰撞及发送区块状态；客户端 Worker 可重建同版 base 并应用权威快照。最后一个订阅者离开活跃范围才停模拟，确认持久化后释放缓存；客户端自行释放不可见view。失败或未加载地块为不可进入，显示轻量载入提示，绝不能虚空坠落。快速旅行须先确保目标 chunk 已载入、碰撞可用，再迁移玩家。地图探索按视口覆盖区域记 bitset；地图远处只读取已知摘要，不触发全量生成。

## 数据契约
ChunkBase: generatorVersion, cx, cy, terrain Uint16Array(1024), flags Uint8Array, biome Uint8Array, staticEntities[]；ChunkDelta: removed/respawnAt、地块改造、建筑/实体变更、lastSettledDay；每玩家 explored bitset 单独保存；所有字段使用稳定 ID。Region 缓存只保存可重算规划，LRU 回收。所有玩家共享唯一 worldId+epoch；可变状态服务端唯一权威，客户端只缓存兴趣范围快照/增量。玩家不得指定Seed、生成新世界或删除世界。

## 验收 WORLD01–06
同 seed/版本/坐标在服务器与客户端、逆序、并发、重新载入生成 byte-identical；至少30 seed×跨区域边界样例，正负坐标与原点，水岸/道路/资源无裂缝重复；每 seed 出生可达且资源充足；长途穿越1000 chunk 内存不持续增长；传送不落入障碍；保存后重新生成底图仍保留修改。用黄金 hash、截图、连通性自动测试和人工景观评审。初始波长、阈值、搜索半径和上限是设计者提出的可调初值，不是实测。

## 共享世界唯一性契约
服务器保存Seed及生成器版本、权威生成碰撞及基础资源，客户端可由服务端下发seed/version重建可见原始图块（公开seed不属于秘密，但正式观察API不揭示未探索资源）。不要求防止用户离线分析公开地形算法；隐藏私有资产/背包绝不下发。服务器 Chunk 生命周期采用所有在线角色兴趣范围并集、引用计数、LRU；附近3×3活跃、5×5加载初值，离屏按D25结算。客户端 Worker仅重建/装饰/寻路，不创造资源。生成消息与状态包均含worldEpoch、chunkRevision，拒绝旧epoch。服务器每个资源实例唯一，采集、建设、再生需原子验证占地和领地权限。出生安全区是所有玩家共用公共区，禁止圈占，出生点从安全格分配；出生交易点可达。区域规划与坐标细节继续有效。世界永久增量及探索地图分开：共享世界变化由服务端保存；每玩家个人探索/标记按身份保存，游客退出删除。长途、并发边界、两个玩家同地块同时操作纳入T20–T29。
