# 环境组合纠错与实施交接
2026-11-27。用户确认V4全部素材视觉验收，同时指出建筑桥梁拼合错误。不得把素材验收等同场景/引擎验收。
## 已复核的原因
V4离线对照图以硬编码ends数组估算道路终点，桥图按画布中心放置，未绑定真实桥面入口；桥面倾斜，路径/河岸独立设置；无跨距、桥墩、通行拓扑。水车小屋直接绘于草地，未检查水轮位置；建筑只按图像底部摆放，无门口、地基、院落与道路连通。建筑桥梁原稿来自低分辨率展示图，仍须精细化。
## 实施要求
- 32px正交逻辑网格与当前美术投影、48×64角色不变；不修改已批准水体像素。
- 桥资产：逐图标注局部像素入口A/B、方向、有效桥面中心线/多边形、支承点、可跨水范围、栏杆/桥面独立遮挡层、碰撞与行走区域。画布宽度不能作为有效跨度。缺少字段不能自动布置；斜桥须明确视觉端点映射至逻辑格，不能任意旋转阴影或透视；若当前图无法匹配网格，制作专门朝向并再验收。
- 区域道路：先确定陆地可达的两侧入口及跨越段，再选择符合跨距的桥，按入口锚点放置。道路端点与桥入口共用坐标；陆地到桥面到对岸必须形成连续可达路径。桥面通行只覆盖实际桥面，水面仍不可通行。跨chunk由同一全局桥ID和端点派生，禁止重复生成；保留服务器权威。
- 建筑：逐图校准接地锚点、占地、门口、入口方向、屋顶遮挡、附属设施及碰撞。道路接至门外可达格，不穿墙。水车需校准水轮接触水域及流向，主体占地在陆地；若不满足地形条件，拒绝放置而非硬贴。院落、台阶、门前路径与建筑功能一致。
- 视觉：复用已批准PNG实际组合，离线检查仅作内部证据；以实际浏览器实时交互场景向用户交付完整景观，新精细化资产需在运行场景中确认。正式Phaser多人、移动端及性能交由具备环境的Agent执行。
## 具体验收
两岸至少各有一条道路实际连到桥面入口；入口位置与道路掩膜重叠，桥面与水域跨越匹配，两侧陆地通过BFS相连，非桥水格不可达；检查跨度不足/入口在水中/岸线变化/跨chunk的拒绝条件。建筑入口与可行走道路相连，实体碰撞不遮挡入口；水车轮与水域相交、主体在岸上。输出无遮挡/遮挡对照，实际PNG截图，坐标、足迹、连接元数据及自动测试结果；未运行的测试不得标通过。当前仅完成问题诊断和交接规范，未实现或验证上述场景修复。
